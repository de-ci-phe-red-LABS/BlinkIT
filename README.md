# BlinkIT — artefact

Source code for *BlinkIT: Linearly Injected Secret Tweak Cannot Protect Against
Integral Cryptanalysis* (INDOCRYPT 2026). Every number in the paper's tables is
regenerated by the commands below; the paper section each command supports is
given in brackets.

## Authors

Soumen Jana, Madhurima Das and Dhiman Saha (de.ci.phe.red lab, IIT Bhilai).

## Layout

```
blinkit/              Python package
  cipher/             reference implementation of all six Blink variants
    blink_ref.py        Blink-64a/64b, recovers the spec's implicit conventions
    blink_ops.py        op-list evaluator (the sequence the C code mirrors)
    blink_gen.py        all six variants vs. the designers' test vectors
  divprop/            bit-based division property, SAT formulation
    blink_divprop.py    CNF model of the components (Sec. 3.2)
    blink_mt.py         multi-tweak model for Blink-64a
    blink_mt_gen.py     multi-tweak bounds for all six variants (Table 4)
    mt_decide.py        the single UNSAT/SAT decision query (Sec. 3.2)
    st_degree.py        single-tweak control (Sec. 5.7)
    validate_divprop.py 12 exhaustive soundness checks (Sec. 5.8)
    compare_tables.py   exact-ANF vs. conventional S-box table (Sec. 5.8)
  cube/               cube sums on the real cipher
    verify_mt.py        multi-tweak cube sums (Table 2, measured column)
    test_free_round.py  free-round extension at k=1,2,3 (Sec. 5.3)
  keyrecovery/
    test_keyrecovery.py end-to-end key recovery at k=1 in Python (Sec. 5.4)
c/                    OpenMP evaluators for the large cubes
  blink_cube.c          distinguishers and measured degrees (Secs. 5.2, 5.3, 5.7)
  blink_attack.c        the key-recovery attack (Secs. 5.4, 5.5)
docs/ARCHITECTURE.md  Blink component by component
```

## Requirements

Python 3.10+ with `python-sat` (`pip install -r requirements.txt`), and a C
compiler with OpenMP. Both C evaluators reproduce the designers' test vector
F.1 on startup and abort if it fails.

```bash
pip install -r requirements.txt
make                      # builds build/blink_cube and build/blink_attack
```

All Python commands are run from this directory with `python3 -m`.

## 1. Implementation and its validation (Sec. 5.1, 5.8)

```bash
python3 -m blinkit.cipher.blink_ref     # unique match among 2048 convention
                                        #   candidates against F.1; cross-checked on F.2
python3 -m blinkit.cipher.blink_gen     # six variants vs. App. F.1–F.6 -> all PASS
python3 -m blinkit.cipher.blink_ops     # op-list evaluator vs. F.1
```

## 2. Division-property model (Sec. 3.2, Table 2 "model" column)

```bash
python3 -m blinkit.divprop.validate_divprop   # 12 exhaustive soundness checks
python3 -m blinkit.divprop.compare_tables     # exact-ANF vs. conventional table:
                                              #   every bound identical
python3 -m blinkit.divprop.blink_mt_gen       # bounds for all six variants (Table 4)
python3 -m blinkit.divprop.st_degree 4 20 23  # single-tweak control: <r> <lo> [hi]
```

The decisive queries of Sec. 3.2 (`<k> <weight>`):

```bash
python3 -m blinkit.divprop.mt_decide 4 50   # UNSAT -> deg(F) < 50 (provable bound)
python3 -m blinkit.divprop.mt_decide 4 49   # SAT   -> the bound is exactly 49
python3 -m blinkit.divprop.mt_decide 4 37   # SAT   -> model declines dimension 37,
                                            #          yet a 2^37 cube balances (below)
python3 -m blinkit.divprop.mt_decide 3 28   # UNSAT (27 is SAT)
python3 -m blinkit.divprop.mt_decide 2 10   # UNSAT ( 9 is SAT)
```

`weight >= w` is monotone: SAT at one weight forces SAT at every lower one, so
a bound is located by probing upward until UNSAT appears.

## 3. Measured degrees and distinguishers (Table 2 "measured" column, Secs. 5.3, 5.7, 5.8)

`build/blink_cube bal <m|f|s> <S-layers> <dim> [trials]` — `m` multi-tweak,
`f` multi-tweak with the free round (S applied before summing), `s` single-tweak.

```bash
build/blink_cube bal m 5 8 3      # k=2: 64/64 balanced at dim 8
build/blink_cube bal m 5 7 3      # dim 7: 16/64 only -> threshold is sharp
build/blink_cube bal m 6 17 3     # k=3: 64/64 at dim 17
build/blink_cube bal m 6 16 3     # dim 16: 10/64
build/blink_cube bal f 6 8 3      # free round: one layer further, still 64/64
build/blink_cube bal f 7 8 3      # it does not chain: 7/64, i.e. noise
build/blink_cube bal s 4 22 3     # single-tweak control (Sec. 5.7)

python3 -m blinkit.cube.verify_mt         # cube sums vs. the real cipher, k=1,2
python3 -m blinkit.cube.test_free_round   # free round, 9/9 configurations, k=1,2,3
```

## 4. Key recovery (Secs. 5.4, 5.5, Table 3)

`build/blink_attack <k> <dim> [trials]`. The RNG seed is a fixed constant, so a
repeated invocation reproduces the same key; `trials > 1` gives independent keys
within one run.

```bash
python3 -m blinkit.keyrecovery.test_keyrecovery   # end to end at k=1, seconds
build/blink_attack 1 4 1
build/blink_attack 2 8 1          # Table 3, row 2^8
build/blink_attack 2 12 1         # Table 3: surplus data degrades the filter
build/blink_attack 2 16 1
build/blink_attack 2 20 1         #   ... until it is vacuous
```

The headline runs (about 30–40 minutes each on 14 threads, 10 minutes on 100 vCPUs):

```bash
build/blink_attack 4 37 3         # 9-layer key recovery, 2^37 cube, three keys
build/blink_cube bal f 8 37 1     # 8-layer distinguisher at full scale
```

Candidate-set intersection (Sec. 5.4). A fourth argument `cubeid > 0` keeps the
key of trial 0 fixed and draws cube `cubeid` (plaintext, base tweak, positions)
from a seed derived from it; `cubeid = 1` reproduces trial 0 exactly. Each run
prints its full per-column candidate lists, and `intersect.py` intersects them:

```bash
for i in 1 2 3 4; do build/blink_attack 4 37 1 $i > cube$i.log; done   # one per machine
python3 intersect.py cube1.log cube2.log cube3.log cube4.log
#   three cubes: product 2^15 -> 2^2;  four cubes: -> 2^1;  true key always inside
python3 intersect.py <(build/blink_attack 2 8 1 1) <(build/blink_attack 2 8 1 2) <(build/blink_attack 2 8 1 3)   # k=2 in seconds
```
